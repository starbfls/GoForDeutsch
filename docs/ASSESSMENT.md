# 阅读与写作判题

这次修复针对两类误判：固定答案列表漏掉合法表达；写作由本地整句匹配判错后，LLM 只能解释这个错误结果。单纯要求模型“更宽松”或只增加几条答案，都无法解决这两个问题。

## 当前流程

1. 阅读、短句写作、段落写作先检查已审定的正确表达。完全匹配示例、合法句式族或已有内容规则时直接通过，模型不能将它推翻，也不消耗模型调用。
2. 未被覆盖的阅读与写作交给配置的 LLM。一次请求同时返回结构化判定与评估，不先由本地判错、再让另一次模型解释。
3. 写作按题目要求检查内容与核心语言结构；段落逐项返回姓名、年龄、喜好、人数、点餐或结账等标准及学生原文证据。服务器检查 ID 完整且唯一、证据真实存在、布尔类型严格、句数和词数限制，以及判定是否自洽。
4. 正确判定的反馈由服务器按已验证的标准生成，不附带模型臆造的“必须换一种说法”。写作不正确时显示结构化问题中的具体下一步。
5. 模型未启用、额度用尽、超时或返回不一致时，已审定正确表达照常通过；不能确认的自由表达显示“暂未确认，答案已保留”，不直接冒充语言错误，也不自动通关。

猜词继续检查已审定目标词、正确词形及少量同义词，不用模糊字符串相似度放行错误。提示、例句和问答仍可使用教学模型；这些动作不是判题，不把空判定当作答错。

## 标准保持明确

- 阅读重在信息：完整原句、合理短答、同义说法与换序均可；人物、物品、数量、金额、否定仍须符合材料。
- 写作同时关注信息与核心语法。合法的物主代词、地点结构、语序与表达方式必须认可；核心谓语或格确实错误、角色信息不符、漏掉任务项目时要求修改。
- 不将“更地道”的个人偏好、参考答案的某个词或可选礼貌词变成隐藏的通关条件。
- 句数要求只执行题目明确提出的要求；模型不能为了认可一个答案而绕过它。
- 不因学生重做、之前答错或用过提示改变语言标准。帮助影响独立完成记录，首次金币规则保持。
- 学生输入与历史片段均作为待评估数据，不执行其中改判、发金币或改变规则的指令。

例如：

| 作答 | 判定 |
| --- | --- |
| Mein Buch ist in meinem Rucksack. | 正确，无须改成 im |
| Mein Buch liegt in meinem Rucksack. | 正确，同一地点信息的合法表达 |
| Mia kauft eine rosa Bluse und einen blauen Rock. | 正确，完整原句同样可以回答 |
| Ich bin vierzehn Jahre alt. | 正确 |
| Ich habe 14 Jahre alt. | 核心年龄动词结构错误，需要修改 |
| 价格24欧元，回答26欧元 | 信息错误 |
| 要求Alex，介绍Ben | 内容不符 |
| 要求不加肉，写 mit Fleisch | 内容不符 |

## 代码位置

- app/curriculum/answer_variants.py：两个单元经过审定的整句族与少量词汇变体，按练习与步骤 ID 组织，整句匹配。
- app/curriculum/school.py / restaurant.py：段落信息标准与常见合法表达。
- app/ai/assessment_prompts.py：阅读、写作共用标准和分别的 Prompt。
- app/ai/reading.py / writing.py：本地确认、一次模型评估、输出验证。
- app/ai/local_assessment.py：本地证据、未确认状态和正确反馈。
- app/services/learning.py：将判定、原文与进度存入既有事务；模型不直接更新数据库或发金币。

新增 accepted_patterns 不向浏览器公开。未采用自动把模型输出写入全局“正确答案库”的方式，避免一次误判永久影响后续学生。新变体可以经审定后补入版本控制中的答案库。

## 未确认的保存方式

阅读和写作 assessment.status 为 correct、incorrect 或 unconfirmed，judge 标记本地或模型提供商。未确认答案原文仍保存；learning_events.correct 为 null，feedback.assessment.status=unconfirmed。界面保留输入、隐藏尚未确认的写作缺项，不要求学生接受一个未经证实的错误结论。

runs.state 中 unconfirmed_attempts 记录未判定的提交次数。提交历史仍计数，但这些次数不作为答错或使用帮助，不扣除独立完成资格。后续确认通过时才推进步骤与发首次奖励。未更改已有完成记录、金币或历史原文，也没有重置课程版本。
